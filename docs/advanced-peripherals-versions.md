# Advanced Peripherals by Minecraft version

The emulator runs the Advanced Peripherals (AP) release of the world's Minecraft version:

| Minecraft | AP      | Source tag followed | Notes                                       |
| --------- | ------- | ------------------- | ------------------------------------------- |
| 1.18.2    | 0.7.31r | 1.18.2-0.7.30r      | the baseline (docs/advanced-peripherals.md) |
| 1.20.1    | 0.7.48r | 1.20.1-0.7.48r      | Forge / NeoForge                            |
| 1.21.1    | 0.7.62b | 1.21.1-0.7.62b      | NeoForge                                    |

Everything below was read from the three jars on Modrinth (sha512 checked against Modrinth's API): the type names
from each peripheral's `PERIPHERAL_TYPE` constant and the block list (`assets/advancedperipherals/blockstates`), and
every `@LuaFunction` name, alias and `mainThread` flag with `javap`. Behaviour comes from the source at the tags above
(GitHub, IntelligenceModding/AdvancedPeripherals), checked against the jars' method lists.
`packages/runner/src/ap-surface-versions.json` holds the method lists; `ap-versions.integration.test.ts` and
`ap-bridges-versions.integration.test.ts` check them and the behaviour below on all three versions.

## Types

Canonical names (the ones in `ADDONS.types` and the world file) are the 1.18.2 ones. A world may use either name;
`getType`, `hasType`, `find` and cable names report the version's (`byVersion` in `packages/runner/src/addons.ts` and
`rom-overlay/rom/ccsim/ap/types.lua`).

| Canonical             | 1.18.2 | 1.20.1   | 1.21.1                                                           |
| --------------------- | ------ | -------- | ---------------------------------------------------------------- |
| `playerDetector`      | same   | same     | `player_detector`                                                |
| `chatBox`             | same   | same     | `chat_box`                                                       |
| `energyDetector`      | same   | same     | `energy_detector`                                                |
| `nbtStorage`          | same   | same     | `nbt_storage`                                                    |
| `environmentDetector` | same   | same     | `environment_detector`                                           |
| `meBridge`            | same   | same     | `me_bridge`                                                      |
| `rsBridge`            | same   | same     | `rs_bridge`                                                      |
| `geoScanner`          | same   | same     | `geo_scanner`                                                    |
| `blockReader`         | same   | same     | `block_reader`                                                   |
| `inventoryManager`    | same   | same     | `inventory_manager`                                              |

(`colonyIntegrator` and the automata cores follow the same snake_case rule on 1.21.1 but are not emulated.)

Only the differences; anything not listed is the same on all three. "From 0.7.48r" means 1.20.1 and 1.21.1.

## Config defaults that changed

`world.ap.config` overrides any of them, on every version.

| Key                         | 1.18.2    | From 0.7.48r  | Meaning                                                               |
| --------------------------- | --------- | ------------- | --------------------------------------------------------------------- |
| `playerDetMaxRange`         | 100000000 | -1            | detector range limit; -1 unlimited                                    |
| `playerDetMultiDimensional` | -         | true          | detectors see other dimensions (range -1)                             |
| `showSpectators`            | -         | true (1.21.1) | spectators in detector results (players with `gamemode: "spectator"`) |
| `chatBoxMaxRange`           | -         | -1            | chat box range limit                                                  |
| `chatBoxMultiDimensional`   | -         | true          | chat reaches other dimensions                                         |
| `chatBoxMessageSize`        | -         | 1024 (1.21.1) | longest message                                                       |
| `chunkyTurtleRadius`        | -         | 0             | chunks around a chunky turtle's that it forces                        |

Players can carry `airSupply`, `respawnPosition {x, y, z}`, `respawnDimension` and `respawnAngle` for
the newer getPlayerPos.

## Not simulated, or not confirmed

- **Random error on getPlayerPos** (`enablePlayerPosRandomError`, off by default) is not simulated.
- **Pocket computers:** the pocket checks (`NOT_ATTACHED_TO_PLAYER`) are there in the source but AP's pocket upgrades
  are not emulated on any version.
- **UTF-8 flag:** the argument is type-checked; the sim's strings are bytes already, so it changes nothing, and the
  chat event's fifth argument is the message as the sim holds it.
- **NBT storage `writeTable`:** the size check is Java serialisation's byte count in the real mod; the sim estimates
  it from the serialised table.
- **Inventory manager on 1.21.1:** a bad side is reported as `Java Exception Thrown: java.lang.NullPointerException`
  without the JVM's helpful message, which was not measured. Item fingerprints are still md5, not 0.7.62b's XXHash64
  (give items an explicit `fingerprint`); `components` are whatever the fixture gives (`components`, else `nbt`).
- **Chunky turtle:** the 600 s record timeout is still not simulated, so a chunk forced by an unequipped chunky turtle
  stays loaded for the whole run.
- **`advancedperipherals.getAddonVersions()`** returns `{}`: the sim has no mod list for AP's integrations.
- **Block states** come from the game data's defaults under the block's own `state`; 1.21.1 still uses 1.18.2's block
  data (docs/turtle.md).
- **Bridges:** storage buses are not modelled (1.21.1 external totals are 0, which is RS's real answer too); the
  1.21.1 plan always succeeds unless the fixture says `craftResult = "MISSING_ITEMS"`; used/missing lists are empty;
  `getUsedBytes` is the job amount; chemicals exist only with a `chemicals` fixture list, and chemical transfers find
  no tanks. Unconfirmed: RS `getCraftingTask` NOT_FOUND arriving as `nil`, 1.21.1 ME `getChemical` without the add-on
  returning `nil`, and 0.7.31r RS `craftFluid`'s second argument not being checked.
- **DisabledPeripheral** (0.7.48r on: a block the config disables still attaches as a stand-in with the same type
  and a `peripheralDisabled` method): the sim never disables a block.
- **ME craftItem / craftFluid** run on the computer thread on every version, as all three jars say (no
  `mainThread`, unlike every other bridge method); before this they waited for a tick on 1.18.2 too.
