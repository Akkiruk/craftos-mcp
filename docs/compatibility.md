# Community programs in the emulator

The emulator's aim is that a program which works here works on a real CC:Tweaked computer, and the other way round.
The best test of the second half is other people's programs: they use the corners of the API that our own tests never
thought of. So we took the projects of the
[awesome-cctweaked](https://github.com/Shlomo1412/awesome-cctweaked) list, the popular ones from each section and
every operating system that still installs, and ran each of them the way a player would: install it with its own
installer, start it, type, click, touch the monitor, and look at the screen.

Every time a project behaved differently from how it does in the game, the cause was looked up in CC:Tweaked's source
and fixed in the emulator, with a test. The last column of the table says what each project turned up.

## What the results mean

- **works**: it installs, starts, draws what it should and reacts to input. The check is a smoke test: a few minutes
  of use, not a play-through.
- **works with notes**: it works, and there is something to know, which the cell says. Mostly a quirk of the project
  itself that a player on a server meets too.
- **broken**: it does not run, and the cell says why.

Two columns, two versions of the mod: CC:Tweaked 1.121.0 (Minecraft 1.20.1 and 1.21.1) and CC:Tweaked 1.101.3
(Minecraft 1.18.2). Some projects need the newer one: Lua 5.2's `goto` and file handles that keep bytes as they are
both arrived in CC:Tweaked 1.109, and the emulator follows each version in that. "needs CC:Tweaked 1.109.0 or newer"
in the older column is the same answer a 1.18.2 server gives.

"Tested" is the commit that was fetched, or a hash of the file. Where it says "what its installer fetched", the
project's own installer downloaded its latest files and there is no single version to name.

## What these projects fixed

Bugs in the emulator that the projects found, all fixed and each pinned by a test
(`packages/runner/src/compat.integration.test.ts`):

- **`_HOST` named CraftOS-PC.** It read `ComputerCraft 1.121.0 (CraftOS-PC v2.8.4)`. Programs look for that name and
  then call what only CraftOS-PC has. It is now what a server says: `ComputerCraft 1.121.0 (Minecraft 1.21.1)`.
- **Windows had a `getGraphicsMode` that raised an error.** The shell's window carried stand-ins for CraftOS-PC's
  graphics functions. A program that asked `if win.getGraphicsMode then` called one and stopped.
- **The root folder listed two folders of the emulator's own**, `/ccunit` and `/results`, beside `rom`. File managers
  showed them.
- **Pocket computers had no `pocket` API**, so `if pocket then` was false on them.
- **`read(n)` on a web response returned what had arrived so far**, often an empty string, instead of n bytes. Music
  players that read a song in chunks played nothing. `read()` also gave the wrong type on text handles, the `binary`
  option was ignored, and CC:Tweaked 1.101.3's text handles did not decode UTF-8.
- **`debug.sethook` was refused** when the emulator ran at CC:Tweaked's speed.
- **Floppy disks**: a world could not start with a disk in a drive, a floppy reported the host disk's size instead of
  125000 bytes, `fs.getDrive` named it `disk` instead of the drive it is in, a full floppy took more, and nothing
  but the computer or a turtle could put a disk in or take it out (the `insertDisk` and `ejectDisk` sim commands now).
- **A backslash before a character that is no escape was an error.** `"\q"` raised `invalid escape sequence`. In
  CC:Tweaked it is `"q"`, and a program packed into one file with raw bytes in a string relies on that.
- **`require "os"` worked**, and so did a few other names that only native Lua knows. In CC:Tweaked it is
  `module 'os' not found`.
- **Speed.** The emulator's Lua is about 8 times faster than CC:Tweaked's. Demos time themselves and one picks a
  different code path on a fast computer, which then breaks. The checks run with `cobaltSpeed: true`, the world
  setting that slows Lua to a server's speed. If your program measures time or does heavy work, test it that way too.

## What is still different

- On CC:Tweaked 1.101.3 a text-mode write that does not fit on a floppy fails at once; the real one buffers 8 KiB
  first. Copying or moving a file onto a floppy is not counted against its space.
- Speakers record what they are given instead of playing it. The checks look at how much audio arrived, not at how
  it sounds.
- The browser build of the emulator has its own web request code, which did not get the `read(n)` fix yet.
- The checks are short. A project marked "works" may still have a difference deeper in. If you find one, report it
  with the "Differs from the real game" issue template: that is exactly what this page is for.

## Running the checks yourself

The checks live in `scripts/compat/`. They hold none of the projects' code: each run fetches what it needs, either
by typing the project's install command into the emulated computer or by a shallow `git clone` into `.cache/compat/`.
Fetched files are only ever run inside the emulator.

    npm run build
    node scripts/compat/run.mjs                      # everything, on CC:Tweaked 1.121.0
    node scripts/compat/run.mjs basalt opus          # some
    node scripts/compat/run.mjs --category os        # library, program or os
    node scripts/compat/run.mjs --mc 1.18.2 --out .cache/compat/out-1.18.2
    node scripts/compat/report.mjs                   # rewrite the table above from the last runs

Screenshots of every step and a text transcript land in `.cache/compat/out/<project>/`. The run exits with 1 when a
project's result is not the expected one, so it can gate a release.

A full run takes about ten minutes and needs the internet. Several installers use GitHub's API without a key, which
allows 60 requests an hour from one address: run the whole set twice in a row and the second run may fail there.

To add a project, give it an entry in `scripts/compat/projects/` (how to install it and what to do with it; the
driver in `lib.mjs` types, clicks, touches monitors, waits for text and takes screenshots) and a line in `notes.mjs`.
